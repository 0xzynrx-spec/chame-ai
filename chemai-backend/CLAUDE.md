# ChemAI Backend — 项目行为准则

## 项目背景

**ChemAI（智辅化学）** 是一个 AI 驱动的中学化学教学辅助平台，目标用户为中国初中和高中化学教师、学生及家长。

### 核心功能模块

| 模块 | 说明 |
|------|------|
| AI Agent 对话系统 | 多角色（教师/学生/家长）智能对话，基于 LangGraph |
| 出题工作台 | 教师组卷、选题、编辑题目，AI 辅助出题 |
| 四维审核引擎 | 科学性 / 难度匹配 / 知识点覆盖 / 区分度 |
| 障碍诊断引擎 | 识别学生学习的障碍类型与迷思概念类别 |
| 题库管理与考试生命周期 | 题目入库、考试发布、判卷、归档全流程 |
| 学生练习与错题本 | 自适应练习、错题收集与复习规划 |
| 家长端 | 学习报告查看、家校沟通 |

### 技术栈

| 层级 | 技术 |
|------|------|
| 语言 | Python 3.11+ |
| Web 框架 | FastAPI |
| ORM | SQLAlchemy（开发阶段使用 SQLite，生产迁移至 PostgreSQL） |
| 向量数据库 | ChromaDB |
| AI 编排 | LangGraph |
| LLM | 通义千问 DashScope API |
| 前端 | Vanilla JS + Vue 3 CDN |
| 迁移工具 | Alembic |

## 行为准则（4 条核心原则）

### 1. 先思考再编码

- 开始实现前，**明确陈述你的假设**。
- 对于不确定的问题，**先发问**而非自行猜测。
- 复杂功能先拟定方案或伪代码，经确认后再动手。

### 2. 简单优先

- 只写解决当前问题所需的**最少代码**。
- 避免过度抽象和"万一将来需要"的预设计。
- 优先选择可读性高的朴素实现。

### 3. 手术式修改

- 只触及**必须修改**的代码，不做无关重构。
- 严格遵循**已有代码的风格**（命名、缩进、注释习惯）。
- 非必要不改动文件结构。

### 4. 目标驱动执行

- 将每个任务转化为**可验证的目标**。
- 写完代码后，立即用测试或手动验证证明目标达成。
- 若目标不可验证，说明需求还不透彻——回去澄清。

## 项目特定规范

### 语言与风格

- **所有代码注释和文档使用中文**。
- Python 代码严格遵循 **PEP 8** 规范。
- 字符串优先使用双引号，f-string 用于格式化。

### 数据与 API

- 数据库模型使用 **SQLAlchemy ORM**，模型定义在 `app/models/`。
- API 遵循 **RESTful** 设计，路由定义在 `app/api/`。
- 请求/响应使用 Pydantic 模型校验。

### 开发方法

- 采用 **TDD（测试驱动开发）**：先写测试（RED），再写实现（GREEN），最后重构。
- 测试文件放置在 `tests/` 目录，与源码目录结构对应。

### 化学与 AI 特化规范

- 化学方程式使用 **LaTeX 格式**：`$...$` 包裹（如 `$2H_2 + O_2 \rightarrow 2H_2O$`）。
- 所有 AI 生成内容**须经审核引擎校验后方可输出给用户**。
- 向量检索（ChromaDB）用于知识点匹配和相似题检索。
- Agent 工具定义放在 `agent/tools/`，不可与业务服务混放。

## 标准开发流程（工具链）

```
思考层 ──→ 规格层 ──→ 实现层 ──→ 质量层 ──→ 流程层
                                          └──→ 骨架层(Git)
```

### 思考层（规划 & 决策）

| 命令 | 用途 |
|------|------|
| `/office-hours` | 讨论架构/方案/瓶颈 |
| `/plan-ceo-review` | 需求 & 产品层面评审 |
| `/plan-eng-review` | 工程 & 技术方案评审 |

以上依赖 Gstack 技能套件。

### 规格层（OpenSpec）

| 命令 | 用途 |
|------|------|
| `/opsx:propose` | 提出变更提案（生成 spec 文档） |
| `/opsx:apply` | 按 spec 实施变更 |
| `/opsx:archive` | 完成后归档 spec |

所有功能变更必须先过 OpenSpec 提案流程。

### 实现层（TDD）

```
写测试 (RED) → Claude 生成实现 (GREEN) → 重构
```

- 使用 `/tdd` 技能驱动标准 TDD 循环。
- 每次完成一个完整的 RED→GREEN→REFACTOR 循环后才开始下一个功能。

### 质量层（Evals）

| 层级 | 说明 |
|------|------|
| L1 单元测试 | 单函数/单类，覆盖率目标 ≥ 80% |
| L2 集成测试 | API 端到端，DB 交互，Agent 工具调用 |
| L3 Golden 测试 | 精选化学典型题作为标准答案对照集 |
| 基线对比 | 每次变更后与上一版本对比准确率/响应时间 |

### 流程层（发布 & 复盘）

| 命令 | 用途 |
|------|------|
| `/review` | 代码审查 |
| `/cso` | 安全 & 合规审查 |
| `/qa` | 质量验证 |
| `/ship` | 发布上线 |
| `/retro` | 项目复盘 |
| `/investigate` | 问题排查 |

以上依赖 Gstack 技能套件。

### 骨架层（Git 工作流）

```
branch → commit → tag → merge → revert（如需）→ push
```

- 分支命名：`feature/<功能>` / `fix/<问题>` / `chore/<杂项>`
- Commit message 使用中文，格式：`<类型>: <简述>`（如 `feat: 添加四维审核引擎`）
- 合并前必须通过 CI 测试
